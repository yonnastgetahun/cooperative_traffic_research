## 1. Driver identities — SOURCE-SUPPORTED conditional representation; **dataset-level mapping UNRESOLVED**

- [Vehicle constructor, 1008–1057](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1008-L1057) accepts a `name`. [Registration, 1149–1159](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1149-L1159) rejects duplicates unless `auto_rename=True`; retains a name-keyed object in `W.VEHICLES` after it leaves the living/running maps.
- **Critical unit distinction:** [`Vehicle` is a vehicle *or platoon*](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1008-L1014); [`World(deltan=5)`](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1699-L1766) defaults to a **five-vehicle packet**, not one individual. [Link admission and capacity updates](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L269-L296) operate in units of `W.DELTAN`.
- **Lossless mapping candidate (NOT implemented):** use one explicit `addVehicle` invocation per original ID, `name=original_id`, `auto_rename=False`, `deltan=1`, `mode="single_trip"`, preserve `p_i`/eligibility as separate immutable fields, and reject any duplicate, missing, extra or grouped ID. A one-packet-per-driver default does **not** satisfy identity.
- **Unresolved:** verified 1:1 mapping against all archived IDs; any consequences of `deltan=1` for mesoscopic flow behavior; C++ engine parity (not examined and **not** a silently approved substitute).


## 2. Original requested departures — **default path BLOCKED; exact integer-tick option SOURCE-SUPPORTED in API but scientific fidelity UNRESOLVED**

- [World parameter and time setup](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1699-L1810): default DELTAN=5 packets and REACTION_TIME=1s produce DELTAT=REACTION_TIME × DELTAN = 5s; DELTAN=1 at the default reaction time still gives a 1s lattice. Original 0.2s requested inputs cannot survive either default unchanged. A fractional REACTION_TIME=0.2 with DELTAN=1 offers a candidate 0.2s lattice, **but it changes the modeled reaction time and flow dynamics**, not merely an output clock.
- [Vehicle initialization](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1065-L1074): in seconds mode, departure_time is set to **int(requested_seconds / DELTAT)**, truncating toward zero. The separately stored departure_time_in_second **multiplies the caller-supplied argument by DELTAT regardless of input mode**, so in seconds mode it is not a trustworthy requested clock at DELTAT≠1; it appears nowhere else in this pinned engine. The separate Boolean departure_time_is_time_step supports integer-tick input and avoids this specific seconds-to-tick division, subject to the physical time-step question.
- **Verified read-only numerical hazard against actual archive:** for DELTAT=0.2, applying the pinned conversion expression to the 1,000 original JSON numeric clocks would place **348 of 1,000** B schedule clocks and **349 of 1,000** C clocks **one 0.2s tick early** compared with exact decimal grid indexes. Example: int(0.6/0.2)=2 instead of expected tick 3 due to binary floating-point representation. For the 12 actual changed drivers, **11 convert to +50 ticks, one to +49 ticks** (veh0626). These are *offline expression results, not executed UXsim observations*. Passing exact original integer tick indices through departure_time_is_time_step is a potential source-supported workaround **not implemented or scientifically qualified**.
- **Requested-to-admitted queue sequencing:** [Vehicle.update](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1179-L1185) moves home → wait and enqueues at W.T ≥ departure_time. Yet [World.exec_simulation](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L2485-L2515) invokes **Node.generate before Vehicle.update** at the same W.T, so a newly eligible vehicle is first eligible for first-link admission **at the subsequent loop iteration**, even if the link is empty. [Node.generate](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L232-L299) may defer admission beyond that for downstream storage/capacity. It logs first link entry at **W.T × DELTAT** ([lines 269–295](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L269-L295)). Thus requested release, home→wait state, first possible admission and actual admitted clock are distinct; a default one-tick boundary difference is source-implied, not a measured outcome.
- **Prospective clock contract:** store immutable original preferred p_i and requested s_i separately; enforce no rounding, one tick integer for each archived 0.2s grid point, and distinguish first eligibility tick from actual first-link admission. Static feasibility still requires an accepted DELTAN/REACTION_TIME change and exact lifecycle accounting, with a frozen precision budget. Never silently offset input requested times to hide the loop ordering.

**Current classification:** a default 5s/1s clock is BLOCKED for exact T1; fractional-reaction-time plus integer-tick API is **plausible source-supported representation but UNRESOLVED scientifically**, especially because the meaning of the physical model changes and exact arrival semantics are not proven.


## 3. Fixed complete original routes — API SOURCE-SUPPORTED; original-route crosswalk **UNRESOLVED**

- [`enforce_route`, 1289–1307](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1289-L1307) records a specified link sequence; [origin admission, 249–258](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L249-L258) requires the specified first link; [downstream selection, 1379–1388](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1379-L1388) checks the next specified link or raises.
- **Paper crosswalk:** `SUMO external edge ID → UXsim directed Link name`, `SUMO junction → UXsim Node`, `r_i → ordered list of those Link names`. Require a bijection for *every used external edge*; assert each consecutive link meets at the same node; keep original origin/destination, no route search or replacement.
- **Caveat:** `enforce_route` itself includes a source TODO about full consistency checking; a valid whole-route map has not been established for the original 1,000 trips. Source capability is **not** a full-cohort route-preservation qualification.

## 4. Junction / queue / spillback representation — meaningful primitives SOURCE-SUPPORTED; **scientific comparability UNRESOLVED**

- [Node transfer logic, 303–358](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L303-L358) checks downstream space and in/out/node capacity, signal group and link merge priority; [origin generation, 269–298](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L269-L298) can withhold insertion; [Node flow-capacity setup, 118–131](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L118-L131) and [Link inflow/outflow limits, 569–582](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L569-L582) supply flow/queue constraints.
- **Non-equivalence risk:** these are mesoscopic capacity/signal/merge-priority mechanisms. They do not, from the inspected source, provide a one-to-one match for all SUMO microscopic turn-by-turn conflict, internal-lane, right-of-way and stochastic car-following semantics. The original synthetic network includes **priority junctions**, which makes that gap materially relevant, not cosmetic.
- **Required static gap register (unperformed):** per original junction: competing turns; movement right-of-way; internal connectors; lane count/capacity; signal policy; merge priorities; queue storage; spillback; and whether proposed UXsim rules represent the same mechanism at an appropriate level. Document any micro-conflict as **NOT REPRESENTATIONALLY COMPARABLE** rather than assuming equivalence.


## 5. All-driver original-preference-to-arrival cost — **per-ID lifecycle SOURCE-SUPPORTED; exact clock/accounting UNRESOLVED**

- [Persistent named dictionary](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1149-L1159) retains objects by driver name after their removal from the living/running indexes; completion and abort are explicitly distinct in [end_trip](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1242-L1267). [Vehicle.update](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1179-L1197) changes home→wait only after node generation in the simulation loop; [Node.generate](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L269-L295) changes wait→run and records first link admission. A route's [traveled_route log](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1447-L1500) can include logged link-entry and final arrival events.
- **Boundary discrepancy requiring explicit qualification:** [end_trip](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1242-L1267) sets arrival_time = W.T (integer tick) and native travel_time=(arrival_time−departure_time)×DELTAT, while updating final-link traveltime_actual through **(W.T+1)×DELTAT**. [record_log](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1529-L1581) appends the terminal end marker at **W.T×DELTAT**. Therefore the native per-person arrival and route-end log share the W.T boundary, but the last-link travel-time statistic employs the W.T+1 boundary. Treat this as a **source-verified one-step convention discrepancy**, not a measured missing second and not proof which is the physically correct destination-crossing time.
- The first eligibility tick may precede first-link admission by at least one step because Node.generate is evaluated earlier in each timestep; the native travel_time field does not separately preserve original preferred departure p_i or requested-versus-admission waiting. In seconds-mode the departure_time_in_second helper has ambiguous/wrong scaling when DELTAT ≠1 (see Requirement 2). Turning off detailed logging is not permission to drop a clock.
- **Paper 1,000-row ledger (not implemented):** original_id, eligibility, preferred p_i, requested s_i, earliest queue-release tick, first-link entry d_i, native end tick, selected physical-arrival boundary a_i, abort/completion status, planned/observed route hashes, matched behavioral controls. Reconcile **(s_i−p_i)+(d_i−s_i)+(a_i−d_i)=a_i−p_i** for each of exactly 1,000 completed drivers, and reconcile total cost Σ(a_i−p_i) without adding road waiting twice.
- **Remaining source-scientific decision:** choose and justify which last-link completion event defines a_i; characterize one-step resolution/measurement uncertainty, and never switch clock conventions between B*/C* or compare incomparable SUMO/UXsim time meanings. An observed abort or incomplete record must be a declared exception, not omitted from the denominator.

**Current classification:** UNRESOLVED for fully faithful preferred-to-arrival cost; persistent names/events alone do not establish the required clock bridge.



## Matched behavioral and stochastic controls — mandatory, not a same-seed assumption

- **Per-ID controlled inputs:** original name, eligibility and original preferred/requested schedule, fixed external link route; original SUMO **printed** per-ID speedFactor is matched between B*/C*, but UXsim exposes no source-verified physically equivalent speedFactor parameter. Any proposed UXsim speed/desired-speed, free-flow, length, node and lane/platoon assumptions must be predeclared and **identical per original driver in both future arms**, or explicitly reported as a representational change. This is *within-UXsim arm parity*, not numerical calibration to SUMO.
- [World.rng initialization](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1790-L1800), [Node.generate sampling](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L249-L266), [node merge selection](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L326-L345) and [vehicle creation colors](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1132-L1141) use/shared-consume world RNG in the pinned Python implementation. Different B*/C* release order or flow state can alter random consumption; matching seed or generated count is insufficient to prove identity-locked counterfactual randomness. Explicit unique IDs do not prevent such coupling.
- Prospective pairing obligation: identify every traffic-affecting random draw; distinguish exogenous individual heterogeneity (must be input-fixed per ID where representable) from endogenous random responses to altered traffic; retain ordering/rng provenance; classify unpaired randomness as a causal attribution limit. **Do not silently enable hard_deterministic_mode**: [the World documentation](https://github.com/toruseo/UXsim/blob/b7e27388757a0e4c64f303c9606a3d5a5ef40388/uxsim/uxsim.py#L1745-L1750) states it materially changes merging and routing behavior.
- Python and C++ implementations must be assessed separately; one cannot silently replace the other. No RNG patch, simulator execution, policy change or source modification is authorized in this milestone.
