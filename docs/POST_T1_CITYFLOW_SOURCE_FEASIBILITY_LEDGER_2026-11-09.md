**Upstream pin:** [cityflow-project/CityFlow `81ee0f47659ca66177a71f81676691c58ee89184`](https://github.com/cityflow-project/CityFlow/tree/81ee0f47659ca66177a71f81676691c58ee89184).

The identical scientific contract applies: original inspected T1 development-seed-2101 **1,000 IDs and immutable preferred departures**, 500 eligible/500 nonparticipants, 12 +10-second requests and 988 unchanged, complete fixed external-edge routes and **all** preferred-departure-to-arrival costs `Σ(a_i−p_i)` under B*/C*. Do not copy SUMO arrivals or change inputs to make CityFlow convenient.

## 1. Driver identity — generated engine IDs SOURCE-SUPPORTED; exact original-ID mapping UNRESOLVED

- [Standard flow loader, `engine.cpp` 106–150](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L106-L150) enumerates input flows `flow_i`, with no original driver-ID field in the inspected schema. [`flow.cpp` 6–20](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/flow/flow.cpp#L6-L20) creates `flow_i_0`, `flow_i_1`, ... on generation.
- [`flow.h` 16–34](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/flow/flow.h#L16-L34) declares one common vehicle template, per-flow interval, integer start/end, counter and `nowTime=interval`. With a one-time flow (`startTime=endTime`) and valid timing, a **one-vehicle-per-flow crosswalk** is plausible, not yet demonstrated for the archived original data.
- **Paper crosswalk (not implemented):** freeze input flow order by an immutable original-ID manifest; map `original vehXXXX ↔ flow_<index>_0`; preserve `p_i`, B*/C* requested times, eligibility, full original route and original ID outside the engine; require 1,000 exact distinct generated/finished IDs with no missing, repeated or extra vehicles. An arbitrary input reorder changes generated names and invalidates a naive ID pairing.
- [Manual injection Python binding](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/cityflow.cpp#L12-L39) exposes `push_vehicle`, but [C++ `Engine::pushVehicle`](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L693-L716) creates IDs `manually_pushed_<counter>`, **also not the original IDs**. Treat it as an alternate prospective path requiring a different crosswalk, not an implemented solution.
- **Unresolved:** static proof each one-time flow is valid and creates exactly one ID, full original-ID/eligibility preservation, deterministic order across B*/C*, engine error/abort behavior and route-invalid flow omission.

## 2. Exact original fractional departure schedules — **BLOCKED in standard flow-file loader**; alternate injection pathway UNRESOLVED

- [Official flow format](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/docs/source/flow.rst#L1-L30) defines inclusive `startTime/endTime`, `interval` and route. However, [the source loader explicitly reads `startTime` and `endTime` as `int`](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L147-L150). [`flow.h` 21–33](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/flow/flow.h#L21-L33) stores integers. The standard file pathway therefore cannot encode original 22.6s, 38.2s, etc. **No rounding is permitted.**
- [Official SUMO converter, `converter_v2.py` 716–729](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/tools/converter/converter_v2.py#L716-L729) explicitly uses `int(float(obj.attrib['depart']))` for both start/end. Its output is **lossy** for fractional T1 times; it is not an approved adapter.
- [`flow.cpp` 6–21](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/flow/flow.cpp#L6-L21) compares its current time to integer starts, then generates vehicles; actual entry may occur later when capacity is unavailable.
- **Important alternate candidate:** [Python `push_vehicle`](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/cityflow.cpp#L12-L39), [generated manual IDs](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L693-L716), and [floating engine `interval`](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L47-L54) suggest that manually injecting at matching simulation ticks **might** represent certain fractional times. The [official documentation](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/docs/source/start.rst) describes configurable step durations; [engine warning bounds](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L167-L175) recommend 0.2–1.5s steps.
- This is **not qualified**: no read-only audit yet establishes the exact lattice for all 1,000 source departures, injection-before/after-step semantics, substep floor/float precision, queue-entry time, replay clock or preservation of matched dynamics. No adapter or external injection controller is authorized in the current phase.
- Distinguish original preferred `p_i`, requested `s_i`, engine creation time and **actual road admission**. Treat loader truncation as a material **standard-path blocker**, not evidence all conceivable CityFlow interfaces are impossible.

## 3. Exact original fixed ordered routes — road/link primitives SOURCE-SUPPORTED; **route fidelity UNRESOLVED**

- [Engine loader](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L118-L133) parses the supplied list of road IDs into a `Route`. [Official flow documentation](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/docs/source/flow.rst#L17-L25) describes these as source/destination and optional anchors, with shortest-path connection.
- **Crucial:** [`Router::updateShortestPath`, 213–242](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/vehicle/router.cpp#L213-L242) constructs a new road sequence by running Dijkstra **between anchor points**; [`Engine::planRoute`](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L267-L280) calls it for pending vehicles. Providing every original external road as an anchor **does not by itself prove** the realized road sequence remains identical. A shortest connection could differ, or a missing laneLink could invalidate it.
- [LaneLink next-drivable selection](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/vehicle/router.cpp#L24-L80) checks lane connectivity for the resulting route; [`set_vehicle_route` binding](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/cityflow.cpp#L36-L39) permits dynamic changes and must **not** be used to substitute alternatives in a frozen T1 scenario.
- **Paper crosswalk:** `SUMO original external edge → CityFlow directed Road`; `SUMO turn connectors → CityFlow roadLink/laneLink`; preserve every `r_i`. Require a static directed/turn-legal path check *and* proof that the engine's anchor expansion has exactly that external-road list for all 1,000 original drivers. Do not claim this has been checked.

## 4. Meaningful junction constraints — structural capabilities SOURCE-SUPPORTED; equivalence UNRESOLVED

- [Official roadnet schema](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/docs/source/roadnet.rst#L5-L80) provides directed roads, lanes, roadLinks, laneLinks and signal phases.
- [Vehicle intersection speed decision](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/vehicle/vehicle.cpp#L337-L371) checks laneLink availability, downstream lane entry and intersection-cross conflict yielding; [engine cross notifications](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L317-L365) update vehicle interactions; [waiting-buffer admission](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L502-L514) models finite admission.
- These are **actual junction mechanisms**, but no per-junction static mapping has been shown between the original SUMO network's microscopic priority/turn conflict rules and CityFlow defaults or converted signals. The included converter is an example, not verified scientifically equivalent geometry/priority.
- **Required gap register:** every original external edge, priority junction, internal connection and lane turn → CityFlow road/roadLink/laneLink; signals; conflicting movements; yield priority; storage, spillback and queue treatment; unrepresentable cases. No geometry-only grid substitute.

## 5. Complete per-ID original-preferred-to-arrival cost — **BLOCKED using standard exposed aggregate/live API**; instrumented event path UNRESOLVED

- [Vehicle creation, `vehicle.cpp` 38–46](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/vehicle/vehicle.cpp#L38-L46) sets `enterTime` to current **engine generation** time; that is not independently shown to equal requested release or actual admission.
- [Finished vehicle handling, `engine.cpp` 284–308](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L284-L308) increments `finishedVehicleCnt` and `cumulativeTravelTime` and removes/deletes the per-ID object. [Public Python bindings](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/cityflow.cpp#L12-L39) expose *currently present* IDs and aggregate average but no persistent per-ID finish event API.
- [`getAverageTravelTime`, 676–688](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L676-L688) additionally mixes cumulative finished and elapsed **currently existing** vehicle times. It is **not** the frozen 1,000-driver `Σ(a_i−p_i)` metric. [Replay logging, `engine.cpp` 518–541](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp#L518-L541) logs positions for currently running vehicles; it does not source-prove exact persistent completion times for every original ID. Polling for disappearance is not a verified exact arrival-event log.
- **Paper ledger:** `original_id, engine_id, eligible,p_i,s_i,engine_generation_time,actual_road_admission_time,completed_arrival_time,completion_flag,actual_route_hash,cost`. Require all 1,000 completed IDs and reconcile `(s_i−p_i)+(d_i−s_i)+(a_i−d_i)=a_i−p_i` without double counting any queue/on-road delay.
- A native per-ID terminal event exists inside the C++ engine, but producing a trusted persisted per-ID arrival/admission trace would require **future separately authorized instrumentation or another source-verified, exact and noninvasive output pathway**. No such change is made here.

## Stochastic and model-family caution

[`flow.cpp`](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/flow/flow.cpp#L10-L16) assigns randomized priorities via the engine RNG; [router lane choices](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/vehicle/router.cpp#L94-L113) also use a random generator. Same numerical seed need not mean per-original-driver matched stochastic behavior after timing perturbations. Do not assume CityFlow is RNG-independent or causally superior to SUMO.
